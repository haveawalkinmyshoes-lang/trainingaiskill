# Вход через личное сообщение Битрикс24

Сотрудник вводит ФИО из закрытого списка, получает шестизначный код в рабочем Битрикс24 и вводит его в том же браузере. Email из Excel используется только для поиска учетной записи. Письма на почту приложение не отправляет.

## Настройка Render

В Environment сервиса neurotrainer задайте:

- `BITRIX_MCP_URL`: HTTPS-адрес MCP.
- `MCP_AUTH_TOKEN`: секрет доступа к MCP, передается только сервером как Bearer-токен.
- `EMPLOYEE_ALLOWLIST_JSON`: закрытый массив объектов `{"fullName":"Фамилия Имя","email":"user@example.com"}`.

Вместо переменной со списком можно использовать Secret File `employees.json` и `EMPLOYEE_ALLOWLIST_FILE=/etc/secrets/employees.json`. В production без списка доступ закрыт. Без подключения к MCP отправить код нельзя; вход по одному ФИО в production не разрешается.

Для подготовки списка: `scripts/import-employees.py путь_к_файлу.xlsx --require-email`. Скрипт распознает заголовки «ФИО», «Имя пользователя», «Email», проверяет адреса, одинаковые имена и общие адреса. Результаты в `app/private/`: JSON для Secret File и env-файл для Add from .env в Render. Excel, список сотрудников и реальные ключи исключены из Git и не обслуживаются HTTP-сервером.

## MCP и отправитель

Клиент использует initialize, notifications/initialized, tools/list и tools/call. Вызывается инструмент `b24_call`. Разрешены только методы `user.get`, `user.current`, `im.message.add`. Пользователь и модель не могут выбирать метод REST или получателя. Для входа выполняются точный поиск по почте, проверка активности и единственного совпадения, затем отправка сообщения числовому ID сотрудника. Вебхуку нужны права чтения необходимых данных пользователей и отправки личных сообщений.

Обычный вебхук отправляет сообщения от имени владельца. При отправке себе сообщение отображается в «Заметках». Для отправителя «Нейротренер» потребуется отдельная интеграция с чат-ботом; текущая версия бота не регистрирует.

## Ограничения

Код криптографически случайный, действует 5 минут, привязан к браузерной сессии. На сервере хранится HMAC. После успешной проверки код уничтожается, cookie и CSRF-токен меняются. Разрешено 5 попыток проверки. Повторный код заменяет предыдущий; повторная отправка доступна через минуту. Лимиты отправки: 5 в час на браузер и почту, 15 в час на адрес соединения, 80 в сутки на процесс, до 3 одновременных отправок. На Render адрес соединения может принадлежать прокси и объединять посетителей.

Браузер не получает почту, список сотрудников, ключ MCP, код или исходные ответы сервиса. Для неизвестного ФИО возвращается такое же общее сообщение об отправке, но доставка не выполняется. Допуск действует 8 часов. Выход закрывает доступ и удаляет связанные тренировки. Интерфейс показывает первые два слова ФИО как фамилию и имя — таблица должна соблюдать этот порядок.

Сессии, коды и ограничители хранятся в памяти одного процесса. Перезапуск очищает их и обнуляет лимиты. Это не распределенное хранилище и не жесткий финансовый лимит провайдера. Для отзыва выданных допусков после изменения списка перезапустите сервис.

Автоматические проверки используют фиктивные адреса и транспорт. Реальная доставка проверена для одного согласованного получателя; он подтвердил сообщение в Битрикс24.
