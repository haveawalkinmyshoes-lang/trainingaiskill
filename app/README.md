# Нейротренер

Локальное приложение с HTML-интерфейсом и подключением к языковой модели. Сценарии, должности, цели и правила читаются из `../02_Инструкция_модели_Нейротренера.md` при запуске сервера. Включены 45 сценариев и 250 вариантов должности, в том числе городские бренд-менеджеры в продажах.

## Запуск в Windows

1. Дважды откройте файл `Запустить Нейротренер.cmd` в папке проекта.
2. Откройте [Нейротренер](http://127.0.0.1:8765).
3. Оставьте окно сервера открытым. Для остановки нажмите Ctrl+C.

Нужен Node.js 22 или новее. На текущем компьютере доступен также встроенный Node.js приложения Codex; файл запуска умеет его находить. Установка npm-пакетов для самого приложения не требуется.

Из терминала: перейдите в папку `app` и выполните `node server.mjs`. Другой порт задается переменной `PORT`.

## Подключение ИИ

Нажмите «Подключение ИИ» в левом меню. Введите API-ключ, название модели и адрес API, сохраните и при желании проверьте соединение. Ключ вводится в поле настроек, а не в чат. По умолчанию используется OpenAI Responses API и модель `gpt-4.1-mini`. Можно выбрать совместимый Chat Completions API; провайдер должен поддерживать JSON Schema.

Альтернатива — скопировать `app/.env.example` в `app/.env`, заполнить `OPENAI_API_KEY` и перезапустить сервер. `.env` исключен из Git и не обслуживается HTTP-сервером. Ключ, введенный через интерфейс, хранится только в памяти сервера и пропадает после перезапуска. Он не возвращается браузеру в ответах API и не сохраняется в localStorage.

Настройки применяются к новой тренировке. При недоступности ИИ приложение показывает ошибку и оставляет неудачный ход несохраненным. Режим ИИ не подменяется демо. Для одного ответа сотрудника выполняются два запроса: персонажу и независимому оценщику. Итог и месячный план формируются отдельными запросами. Проверка соединения также делает один короткий запрос. Тарификация зависит от выбранного провайдера.

Без ключа можно проверить весь путь в явно обозначенном демо. Демо использует шаблонные ответы и условные оценки, поэтому не предназначено для оценки навыка сотрудника.

## Как пользоваться

Тема → должность из списка → подходящая ситуация → диалог → разбор → два вопроса рефлексии → план на следующий месяц. В городских вариантах бренд-менеджера применяется профиль специалиста продаж.

После каждого содержательного ответа показываются оценка шага и наблюдаемые компетенции с целевыми уровнями. Шкала 0–3 с шагом 0,5. Сервер проверяет допустимость компетенций, значение оценки и наличие цитаты в реплике сотрудника. При недостатке данных остается «—», а не ноль. Итог не является аттестационным уровнем сотрудника.

Enter отправляет сообщение, Shift+Enter добавляет строку. «Подсказка» дает помощь с отметкой в отчете. Команды «Пауза», «Продолжить» и «Стоп» не оцениваются. Оценки шагов сохраняются в истории; итог учитывает исправления, а не усредняет все реплики.

Месячный план содержит четыре периода, конкретную практику и способы проверки. Даты вычисляются по локальной дате сессии в Москве. Результат и домашнее задание можно скачать в Markdown.

## Хранение и границы локальной версии

Сервер слушает только `127.0.0.1`. Сессии и настройки находятся в памяти; перезапуск их очищает. Вкладка восстанавливает текущую сессию после обновления, пока сервер работает. Сохраняйте нужные результаты кнопкой скачивания. Напоминания и отправка отчетов руководителю не настроены.

Для развертывания на сотрудников отдельно потребуются учетные записи, постоянное хранилище, разграничение доступа и серверная конфигурация API-ключа. Текущая версия рассчитана на локальное использование одним человеком.

## Проверки

`node --test tests/domain.test.mjs tests/integration.test.mjs` проверяет маршрутизацию, разграничение данных, половинную шкалу, цитаты, даты и полный путь до плана. API проверяется с тестовым провайдером, без реального ключа и внешних запросов. `tests/browser.mjs` проходит пользовательский путь в браузере и делает снимки настольной и мобильной версий; для него нужны Playwright и Edge из текущей среды.

Проверка настоящей модели и калибровка оценивания с методологами остаются отдельным пилотом.

Использована [официальная документация Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [описание GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). В Responses API применяется JSON Schema и `store:false`.
